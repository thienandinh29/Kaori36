# Spec: a teacher before the exercises and the test (lesson player, grammar map first)

The owner's requests (16 Nov 2026): (1) on the grammar map, "a teacher teaches me first, then gives me exercises and a
test"; (2) teach like OpenMAIC (`THU-MAIC/OpenMAIC`, MIT) and add it to this project. Document only: nothing is built
until the owner decides the points at the end.

## What OpenMAIC does, and what we take
Read: the README, plus our earlier code study at commit `6e51916` (`docs/research/openmaic-study.md`, idea 1). **Not
re-read today:** the code itself; of its 21 action types the study names five (`speech`, `wb_open`, `wb_draw_text`,
`spotlight`, `laser`). The full list is read from `packages/@openmaic/dsl/src/action.ts` before the data model is fixed.

| OpenMAIC | NodeTrail |
|---|---|
| A lesson is scenes (slides, quiz, simulation, project) made from an outline | **Take.** A lesson is a few scenes; scene types here: why, uses, form, versus-Vietnamese, examples, try-it, wrap-up |
| An AI teacher speaks, spotlights, draws on a whiteboard | **Take.** Sena speaks (subtitles always), spotlights words, writes on a board |
| Typed actions, never free UI control; fire-and-forget vs wait-until-done; one action language for live and offline | **Take.** Same split. Our `ask` action takes a real item and hands the answer to the engine |
| Playback state machine `idle → playing → live` | **Take.** `idle → playing → paused → live` (live = the learner asks Sena a question) |
| Agents (teacher, AI classmates, roundtable debates) orchestrate the class | **Leave.** The engine decides; one teacher explains. Classmates and debates cost more, add latency and cannot be checked by code |
| Everything generated by the model | **Change.** Generated once, **offline**, checked by code and a second model, reviewed, then played the same way every time |
| Project-based learning, 3D simulations, MP4 export | **Leave** (not needed for grammar) |
| AI grades quizzes | **Leave.** Answer keys grade; the model never grades |
| Proficiency tier by a weighted heuristic | We keep per-concept BKT over the prerequisite graph |

Code reuse: **none planned.** OpenMAIC is a large pnpm workspace (Next.js 16, React 19, its own PostgreSQL), ours is a
different stack, and adding dependencies needs the owner's approval. MIT would allow copying a part with a notice in
`NOTICE`; that would be proposed separately.

## The lesson as data
`data/lessons/english-ielts/<node>.yaml` (CC BY-NC-SA, like the items), one file per hidden node and a shorter
overview per milestone. A lesson is an ordered list of scenes; a scene is an ordered list of actions. Short example:

```yaml
node: present-perfect
scenes:
  - id: why
    actions:
      - {do: say, vi: "Bạn muốn nói \"Tôi đã sống ở Hà Nội 5 năm\" mà vẫn đang sống ở đó? Thì quá khứ đơn không đủ."}
      - {do: show_example, id: ex1, en: "I have lived in Hanoi for five years.", vi: "Tôi đã sống ở Hà Nội năm năm (và vẫn đang sống).", target: "have lived"}
      - {do: spotlight, example: ex1, range: target}
      - {do: say, vi: "Trong IELTS Speaking Part 1, câu này trả lời \"How long have you lived here?\"."}
  - id: form
    actions:
      - {do: board_table, rows: [["+", "have/has + V3"], ["−", "have/has not + V3"], ["?", "Have/Has + S + V3?"]]}
      - {do: speak_en, text: "She has worked here since 2020."}
  - id: try
    misconceptions: [past-simple-for-unfinished]
    actions:
      - {do: ask, checkpoint: pp-try-1}   # graded by key, aided (see rules)
```

Actions (small and closed; each is validated by schema, so a model cannot invent new ones):
`say` (Vietnamese narration), `speak_en` (an English sentence read by the server voice), `show_example`, `spotlight`
(a word or phrase inside an example), `board_write`, `board_table`, `board_timeline` (past, now, future, with points),
`board_arrow`, `board_clear`, `ask` (a checkpoint), `pause` (wait for "Tiếp"). Fire-and-forget: `spotlight`, `board_*`.
Wait until done: `say`, `speak_en`, `ask`, `pause`. The board draws structured shapes from the data, never free SVG
written by a model.

## What the learner sees
A lesson page `/hoc/{slug}`: Sena at the side, the board and the example card in the middle, subtitles below, buttons
**Tạm dừng / Nghe lại / Câu trước / Câu sau / Hỏi Sena / Bỏ qua bài học**. About 2–3 minutes. Phones first, like the
rest of the app. Everything works with sound off.

Order on the map: **Bài học → Luyện tập → Kiểm tra.** The milestone panel opens on the lesson, and
"Tôi đã biết, kiểm tra luôn" skips it (the "test to unlock" rule stays). After a wrong answer, the explanation offers
"Xem lại cảnh này" for the scene tagged with that misconception.

## Voice
- **English examples:** the server voice we already run (Piper `en_GB-cori-high`, `/speech`).
- **Vietnamese narration: no good voice yet.** The Piper voice is English only. Default: Vietnamese as subtitles and
  the English read aloud. Piper's catalogue lists Vietnamese voices; **their licences and quality are not checked**
  and would need the same pinning and licence check as the English one. Browser Vietnamese voices vary by device;
  lesson text is public, so using them is allowed, but quality is not guaranteed.

## How the engine and the teacher fit together (our difference)
- **Reading is not evidence.** A lesson never changes mastery and never unlocks anything. Sena does not praise reading.
- **`ask` checkpoints are aided.** They are graded by key, recorded, and weighted like an answer given after help
  (the mastery gate in `specs/mastery-gate/`: no confirmed mastery without unaided correct answers). Only the later
  exercises and the milestone test count as unaided evidence.
- **The engine chooses scenes.** For a learner who failed on a misconception, the next step can be that lesson's
  tagged scene, shown in the "Vì sao?" trace ("Sena cho xem lại cảnh X vì bạn chọn Y"). The model does not choose.
- **No lesson sentence is a test sentence.** Code checks that no example or checkpoint repeats a question's sentence
  or contains its answer.

## Where lessons come from
1. **Authored by the agent as drafts now**, labelled "Bản nháp — chưa được giáo viên duyệt" until the owner reviews
   each lesson (same route as the items and misconception explanations).
2. **Generated offline** (phase C) by the model through the gateway (outline → scenes → actions, JSON validated and
   repaired, retried with a delay ceiling), then checked by code (below), then by a second model family that reads only
   the cited text.
3. **Cited** once a grammar source's licence is verified (`wikibooks-grammar` or an open ESL textbook in
   `data/sources/english-candidates.yaml`). Until then there is nothing to cite, so lessons stay drafts and no verifier
   result is claimed.

Checked by code: every hidden node and milestone has a lesson; actions come from the closed list and are valid; each
`spotlight` target exists in its example; each example contains the form taught; each `misconceptions` entry exists;
length 90–240 s by a reading-speed estimate; Vietnamese is NFC; no overlap with test items. A shortlist pass picks the
risky claims (rules with "always" or "never", exceptions, numbers) for the second model.

## Ask Sena (phase D, live)
The one runtime model call. The learner asks about the lesson; Sena answers in Vietnamese through the gateway task
`lesson_qa`, grounded in the lesson text (and a cited source once there is one). A deterministic check refuses an
answer that contains the answer key of any question on that node (the hint-leak check). Counted in the learner's plan
limits (`specs/plans/`). No answer without grounding.

## Phases and gates (each gate is measured)
| | What | Gate |
|---|---|---|
| A | This spec, three decisions | The owner decides |
| B | Action language, schema, player (subtitles, spotlight, board, English audio), **3 pilot lessons** (present perfect, first/second conditional, articles) and the code checks | The owner finishes all three and rates each 1–5 for clarity; the code checks pass; the lessons take 2–3 minutes |
| C | All 19 node lessons and 10 milestone overviews through the offline pipeline, review queue for the owner | Share of lessons the owner accepts without edits, with an interval; second-model disagreement rate |
| D | Ask Sena and engine-chosen scenes | No answer-key leaks in a planted-leak set; every replay shown in the trace |
| E | Later, if wanted: Vietnamese voice; the same player for other subjects (the topic research path, with figure specs and cited chunks) | Decided then |

**Does it help?** First-try accuracy on a node's questions with the lesson seen versus skipped, and remediation loops
per node. With one or a few learners the numbers will be too small to prove it; the report says so.

## Cost
Playback costs nothing per learner. Generating 29 lessons offline is a few cents of model calls. Ask Sena is bounded by
the plans. No new dependency in phase B.
